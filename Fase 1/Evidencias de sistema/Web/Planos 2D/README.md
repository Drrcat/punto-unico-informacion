# Planos 2D de la sede de ejemplo

Esta carpeta reúne los planos bidimensionales de los pisos 2 y 3 de la sede de ejemplo (Duoc UC, sede Puente Alto), que el tótem muestra en su mapa interactivo. Los planos se trazaron en Figma a partir de los planos de la sede, se exportaron como SVG y después se normalizaron con la herramienta `backend/herramientas/exportar_planos.py`, de modo que cada espacio quedara identificado de la misma forma en el dibujo y en la base de datos.

Cada piso es un archivo independiente, `piso-2.svg` y `piso-3.svg`, y ambos comparten el mismo cuadro de dibujo (`viewBox="0 0 1589 444"`). Gracias a eso, un piso puede reemplazar al otro en pantalla sin que cambien la escala ni la posición de las torres. Dentro de cada archivo, cada sala, oficina o área es un grupo `<g>` cuyo id coincide con el valor de `svg_element_id` del espacio correspondiente en la tabla `espacio`; por ejemplo, `P2-T1-S01` identifica la sala 01 de la torre 1 del piso 2. El piso 2 tiene 42 espacios y el piso 3 tiene 57, que suman los 99 espacios que carga la base de datos. Los demás elementos del dibujo (circulaciones, bordes, vidrios y decoración) no corresponden a espacios, y la mayoría está agrupada en capas cuyo id empieza con `capa-`.

El backend entrega cada plano mediante `GET /api/pisos/{id}/plano`, tomándolo de la carpeta que indica la variable de entorno `PLANOS_DIR`, y la aplicación web (`mapa-totem.html`) lo muestra y resalta el espacio buscado a partir de su id. La copia que usa la aplicación está en `assets/planos/`, dentro de la carpeta `Web`; los archivos de esta carpeta son la copia de evidencia. Los archivos `piso-2.png` y `piso-3.png` son vistas previas del mismo dibujo para consulta rápida y la aplicación no los utiliza.

Si un plano cambia, se vuelve a exportar con `exportar_planos.py` y se conserva el id de cada espacio, para no perder el vínculo con la base de datos. Por ahora solo existen los pisos 2 y 3, que son los que tienen espacios cargados.
